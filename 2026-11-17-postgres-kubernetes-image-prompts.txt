"6. Availability is not disaster recovery"
"HA keeps service running after some failures. Backups let you recover earlier data. Replication can copy an accidental DELETE to every replica."
Small diagram "Accidental DELETE" -> "Primary" -> "Standbys" with red caution mark. Distinct separate recovery flow "Base backup + archived WAL" -> "Restore NEW cluster" -> "Validate data + app" -> "Controlled cutover".
"PITR = point-in-time recovery. It needs a valid base backup and an unbroken WAL archive covering the target."
"7. Risks → practical controls"
Seven well-separated rows:
"Node / zone outage → Spread instances across failure domains; test failover and app reconnects."
"Replication lag → Async failover can lose recent writes. Choose replication policy from the business RPO."
"Synchronous replication → Stronger commit durability can add latency or block writes when required replicas are unavailable."
"Bad SQL / lost cluster → Keep protected backups outside the cluster; restrict deletion rights; rehearse restore."
"Slow or full disks → Benchmark storage; monitor latency, capacity and WAL growth; reserve headroom."
"Bad rollout / upgrade → Review GitOps changes; test supported upgrade paths; plan recovery before production."
"Credential exposure → Least-privilege DB roles and RBAC, TLS, restricted networking, encrypted storage and backups."
"8. Incident example: checkout DB fails"
Diagram "Primary unavailable" -> "Operator promotes eligible standby" -> "Write Service points to new primary" -> "Application reconnects".
"Existing connections may break. Use bounded retries; handle uncertain transactions safely to avoid duplicate orders."
"Cross-cluster disaster recovery needs a separate tested plan."

"RPO = acceptable data loss. RTO = acceptable recovery time."
"Example targets only: RPO ≤ 5 min; RTO ≤ 30 min."
"Restore to an isolated environment; check records and application behavior; measure actual recovery time."
"Monitor query latency, errors, connections, replication lag, disk usage and backup/WAL archive health."
